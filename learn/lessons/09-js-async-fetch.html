09. Asinxron JS va fetch

Serverdan ma'lumot olish darhol bo'lmaydi — u vaqt talab qiladi. JavaScript bu vaqtda to'xtab turmaydi, ishni davom ettiradi. Shu "kutish" mexanizmini o'rganamiz: Promise, async/await va fetch.

Sinxron va asinxron

Nega shunday? Agar JS kutib turadigan bo'lsa, sahifa "muzlab" qolardi: tugmalar bosilmaydi, animatsiya to'xtaydi. Shuning uchun uzoq ishlar (server so'rovi, taymer) chetga qo'yiladi va tayyor bo'lganda bajariladi.

Promise — "keyinroq beriladigan qiymat"

async / await — o'qishga qulay shakl

Qaysi birini ishlatish kerak? Yangi kodda async/await. .then() ni bilish kerak, chunki eski kodda ko'p uchraydi. await faqat async funksiya ichida ishlaydi.

fetch — serverdan ma'lumot olish

Quyidagi misol haqiqiy so'rov yuboradi: kurs papkasidagi assets/demo-odamlar.json faylni o'qiydi. Bu xuddi o'z API'ingizdan ma'lumot olishning o'zi.

Yuklanish holati bilan to'liq namuna

Real ilovada foydalanuvchi kutayotganini bilishi kerak. Uchta holat bo'ladi: yuklanmoqda, tayyor, xato. Har birini ko'rsatish — professional frontendning belgisi.

Serverga ma'lumot yuborish (POST)

async function sozlamaSaqla(sozlama) {
  const javob = await fetch("/api/settings", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(sozlama),          // obyektni matnga aylantiramiz
  });

  if (!javob.ok) throw new Error("Saqlanmadi: " + javob.status);
  return await javob.json();
}

// Ishlatish:
try {
  const natija = await sozlamaSaqla({ til: "uz", quyiYosh: 18, yuqoriYosh: 30 });
  console.log("Saqlandi", natija);
} catch (err) {
  console.error(err.message);
}
Soyla'da bu qanday Mini App sozlamalarni saqlaganda aynan shunday POST so'rov yuboradi, server esa app/api/webapp.py da uni qabul qilib, PostgreSQL'ga yozadi. Telegram'ning initData si ham shu so'rov bilan birga ketadi — server foydalanuvchi haqiqatan kim ekanini tekshirishi uchun (app/telegram_auth.py).

  • faqat online: true bo'lganlarini ko'rsating;

Namuna yechim 
async function korsat() {
  chiqish.textContent = "Yuklanmoqda...";

  try {
    const javob = await fetch("../assets/demo-odamlar.json");
    if (!javob.ok) throw new Error("HTTP " + javob.status);

    const malumot = await javob.json();
    const onlaynlar = malumot.odamlar.filter(odam => odam.online);

    chiqish.innerHTML = "";

    if (onlaynlar.length === 0) {
      chiqish.textContent = "Hozir hech kim onlayn emas";
      return;
    }

    onlaynlar.forEach(function (odam) {
      const karta = document.createElement("div");
      karta.className = "karta";
      karta.textContent = `${odam.ism}, ${odam.yosh} — ${odam.shahar}`;
      chiqish.append(karta);
    });

  } catch (err) {
    chiqish.innerHTML = "";
    const xato = document.createElement("div");
    xato.className = "xato";
    xato.textContent = "Xato: " + err.message;
    chiqish.append(xato);
  }
}

Xulosa

  • JavaScript uzoq ishlarni kutib turmaydi — ular Promise orqali keyinroq tugaydi.
  • async funksiya + await — o'qishga eng qulay shakl.
  • fetch dan keyin javob.ok ni albatta tekshiring.
  • await javob.json() — ikkinchi await ni unutmang.
  • Har bir so'rov uchun uchta holatni ko'rsating: yuklanmoqda / natija / xato.
Tekshiruv savollari

1. fetch 404 qaytarsa, catch ishlaydimi?
Yo'q. javob.ok ni o'zingiz tekshirib, throw qilishingiz kerak.

2. const m = fetch(url) da m nima bo'ladi?
Promise. await yozish kerak.

3. Ikki so'rovni bir vaqtda yuborish uchun nima ishlatiladi?
Promise.all([...]).
